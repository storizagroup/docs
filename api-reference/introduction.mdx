The Storiza API is a JSON REST API. Everything in this reference can be called with an [API key](/authentication); the catalog endpoints (plans, templates, datacenters, currencies) need no key at all.

```text Base URL
https://api.storiza.store
```

## Authenticate

Send your key as a bearer token on every request:

```bash
curl https://api.storiza.store/profile/information \
  -H "Authorization: Bearer $STORIZA_API_KEY"
```

Each endpoint page lists the **permission** the key needs, such as `vps:read` or `apps:write`. Reading needs `:read`; anything that changes something needs `:write`. See [Permissions](/authentication#permissions).

## Try it here

Every endpoint page has a playground. Paste your key into the **Authorization** field, fill in the parameters and press **Send** — the request goes to the live API with your key, so it acts on your real account.

<Warning>
  Requests sent from the playground are real. Creating, deleting or paying for something here does exactly that.
</Warning>

## IDs

Resources are identified by UUIDs, such as `0234c235-ee24-40ce-a8bc-b0f944484a6a`. Some paths call a server's id `vmId`, `vpsId` or `id` — they are all the same server id.
