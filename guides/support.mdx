A ticket is one conversation, whichever way you use: reply by email to a ticket you opened in the dashboard and the reply lands in the same thread, and the other way round. Keep the ticket reference (`TKT-…`) in the email subject when you reply so it reaches the right conversation.

### What to include

- **Which server or app** — its name and id.
- **What you did, what you expected, what happened instead.**
- **For API problems:** the endpoint, the time, the HTTP status and the full error body — especially `code`. Never include your API key.

## Tickets from the API

With a key holding `support:write`:

```bash
curl -X POST https://api.storiza.store/support/tickets \
  -H "Authorization: Bearer $STORIZA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "subject": "Server web-1 unreachable", "message": "Since 14:00 UTC the server does not answer on port 443.", "priority": "normal" }'
```

| Task | Endpoint |
| --- | --- |
| List your tickets | `GET /support/tickets` |
| Read a conversation | `GET /support/tickets/{id}/messages` |
| Reply | `POST /support/tickets/{id}/messages` |
| Close | `POST /support/tickets/{id}/close` |
| Count unread replies | `GET /support/unread` |

Replying to a closed ticket opens it again.
